Step 2 · AuthService

AuthService · sign up

The class starts with final FirebaseAuth _auth = FirebaseAuth.instance;

lib/services/auth_service.dartAuthService
  Future<String?> signUp({
    required String name,
    required String email,
    required String password,
  }) async {
    try {
      final UserCredential credential = await _auth
          .createUserWithEmailAndPassword(email: email, password: password);
      await credential.user?.updateDisplayName(name);
      return null;
    } on FirebaseAuthException catch (e) {
      return messageFor(e.code);
    }
  }

Returns String?:

Successnullit worked
Errora textthe error to show the user
createUserWithEmailAndPassword creates the account and signs the user in
credential.user is the new user; updateDisplayName(name) saves the name in Firebase
try … on FirebaseAuthException catch (e) : new today. Dart tries the code; if Firebase says no, it jumps to catch

credential.user?. with ?. means "only if the user is not null".

Step 2 · AuthService

When things go wrong: friendly messages

AuthServiceString messageFor(String code)
    return switch (code) {
      'email-already-in-use' =>
        'This email already has an account. Try logging in.',
      'invalid-email' => 'This email address is not valid.',
      'weak-password' => 'Password is too weak. Use at least 6 characters.',
      'invalid-credential' ||
      'user-not-found' ||
      'wrong-password' => 'Wrong email or password.',
      'user-disabled' => 'This account has been disabled.',
      'too-many-requests' => 'Too many attempts. Wait a minute and try again.',
      'network-request-failed' => 'No internet connection. Check your network.',
      'operation-not-allowed' =>
        'Email/Password sign-in is not enabled in the Firebase console.',
      _ => 'Something went wrong ($code). Please try again.',
    };

A FirebaseAuthException has a code: a short text such as 'invalid-credential'. Users should never see it.

Firebase sendsThe user sees
invalid-credentialWrong email or password.
email-already-in-useThis email already has an account. Try logging in.
network-request-failedNo internet connection. Check your network.

switch picks the line whose code matches; || means "or"; _ means "any other code".

Email enumeration protection (on by default for new projects since September 2023): a wrong email or a wrong password both give invalid-credential, so strangers cannot find out which emails have accounts. user-not-found / wrong-password only appear in old projects.

This is the body of String messageFor(String code) in AuthService. The codes come from the firebase_auth 7.0.1 documentation.

lib/sign_up_page.dart_SignUpPageState
  Future<void> _createAccount() async {
    final name = _nameController.text.trim();
    final email = _emailController.text.trim();
    final password = _passwordController.text;
    final messenger = ScaffoldMessenger.of(context);
    final navigator = Navigator.of(context);
    // Simple checks first: no need to ask Firebase about empty fields.
    if (name.isEmpty || email.isEmpty || password.isEmpty) {
      showAppSnackBar(messenger, 'Please fill in all fields.', isError: true);
      return;
    }
    if (password.length < 6) {
      showAppSnackBar(messenger, 'Use at least 6 characters.', isError: true);
      return;
    }
6+Firebase needs passwords of 6+ characters: checking here saves a trip to the server
returnStops the method early: Firebase is not called

showAppSnackBar(messenger, text, isError: true) is our helper: red for errors, green otherwise (lib/widgets/app_snack_bar.dart)

Step 4 · Login page

Login page · _login()

lib/login_page.dart_LoginPageState
  Future<void> _login() async {
    final email = _emailController.text.trim();
    final password = _passwordController.text;
    final messenger = ScaffoldMessenger.of(context);
    // … the same empty-field check as on the sign-up page …
    setState(() => _isLoading = true);
    final error = await _authService.signIn(email: email, password: password);
    // On success, AuthGate replaces this page, so check `mounted` first.
    if (mounted) setState(() => _isLoading = false);
    if (error != null) {
      showAppSnackBar(messenger, error, isError: true);
    } else {
      showAppSnackBar(messenger, 'Welcome back!');
    }
  }
No Navigator.push to Home any more: the AuthGate switches to HomePage by itself
That is why we write if (mounted) setState(...): after a successful login this page may already be gone

The SnackBar still appears, on the Home page, because messenger belongs to the whole app

Step 5 · AuthGate

AuthGate · stay logged in

lib/auth_gate.dartAuthGate · build()
    return StreamBuilder<User?>(
      stream: AuthService().authStateChanges(),
      builder: (context, snapshot) {
        if (snapshot.connectionState == ConnectionState.waiting) {
          return const Scaffold(
            body: Center(child: CircularProgressIndicator()),
          );
        }
        if (snapshot.hasData) {
          return const HomePage();
        }
        return const LoginPage();
      },
    );
StreamA list of values that arrive over time (like a radio: news keeps coming)
StreamBuilderFutureBuilder's brother (Lecture 15): it rebuilds every time a new value arrives
authStateChanges()Sends the current user at start, then a new value on every sign in and sign out
restartFirebase saves the signed-in user on the phone: the first value is that user, so Home opens directly

  Future<String?> sendPasswordReset(String email) async {
    try {
      await _auth.sendPasswordResetEmail(email: email);

Wrap-up

Summary

Remember

  • TextEditingController: create in State, read .text, dispose()
  • AuthService: signUp (+ updateDisplayName), signIn, signOut, sendPasswordReset; returns null or a message
  • Errors: FirebaseAuthException.code → messageFor; wrong email or password = invalid-credential
  • Loading button + green / red SnackBars; take messenger before await, check mounted after
  • AuthGate = StreamBuilder + authStateChanges(): Login or Home, and you stay logged in
